# P0 スキャン技術スパイク記録

実機での検証結果を記録する。検証画面: アプリ内「バーコードスキャン スパイク」

## 前提知識(実装時の調査結果)

- VisionKit `DataScannerViewController` は **A12 Bionic 以降 + iOS 16+** が必要(`isSupported` で判定)
- **UPC-A は EAN-13(先頭 0 付き)として検出される**。VisionKit / AVFoundation とも独立したシンボロジー指定はない → 出力時にそのまま保存する方針(PRD の UPC-A 対応はこれで満たす)
- カメラはシミュレータ非対応のため実機必須
- `isAvailable` はカメラ権限を含めた実行時可否を返す

## 発見された問題と対策(P3 の設計に反映)

**書籍の2段 JAN(上段: ISBN 978…、下段: 価格コード 192…)が交互に連続受理される。**
クールダウンが「同一コードのみ」対象だったため、2つの異なるコードが画面に入ると
A → B → A → B と交互にすべて受理されてしまう(本実装ではデータ誤登録に直結)。

対策(スパイクに実装済み、実機検証 OK):
1. **読取範囲の中央帯制限** — VisionKit `regionOfInterest` / AVFoundation `rectOfInterest` で
   画面中央の帯(高さ35%)のみ検出対象にし、黄色のガイド枠で狙いを可視化。トグルで ON/OFF 可
2. **グローバルクールダウン** — 直前の受理から 1 秒間は**別のコードでも**無視する
3. **再アーム方式** — 視界に入り続けている同一コードは 1 回だけ受理。再登録は
   読取範囲から外して 1 秒以上経過後にかざし直す(`ScanArbiter` として Core に実装)

- [x] 実機再検証(2026-07-27): 2段 JAN で狙ったコードだけ読めること、同一コードの
  かざし続けで連続登録されないこと、枠外→かざし直しで再読取できることを確認
- **P3 のスキャン本実装は「ガイド枠 + ScanArbiter(再アーム + グローバルクールダウン)」方式を採用する**

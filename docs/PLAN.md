# 開発計画書

docs/PRD.md・docs/DESIGN.md に基づく MVP 開発の進行計画。

## 方針

1. **最大リスクを最初に潰す** — このアプリの成否はスキャン体験で決まる。VisionKit はシミュレータで動かず実機必須のため、最初に実機で技術検証（スパイク）を行う
2. **シミュレータで進められる部分を厚くする** — 取込・一覧・出力はシミュレータ＋単体テストで高速に開発できるので、スキャン検証と並行して進める
3. **各フェーズの終わりに「動くもの」がある** — フェーズごとに完了条件（動作確認できること）を定義する

---

## フェーズ一覧

| フェーズ | 内容 | 規模感 |
|---------|------|--------|
| P0 | プロジェクト準備 + スキャン技術スパイク | S |
| P1 | データモデル + 取込（S2, S3） | M |
| P2 | レコード一覧 + ホーム(S4, S1) | M |
| P3 | スキャン本実装（S5） | L |
| P4 | 出力（S6） | S |
| P5 | 仕上げ（非機能要件・エッジケース） | M |
| P6 | MVP 受入テスト | S |

規模感の目安: S = 半日〜1日 / M = 1〜2日 / L = 2〜4日（集中作業時）

---

## P0: プロジェクト準備 + スキャン技術スパイク

**目的**: 開発基盤を作り、最大の技術リスク（カメラ読取）を最初に検証する。

作業:
- [ ] Xcode プロジェクト作成（iOS 17+ / SwiftUI / SwiftData）
- [ ] `Info.plist` に `NSCameraUsageDescription` 追加
- [ ] DESIGN.md 6章のディレクトリ構成を作成
- [ ] **スパイク**: 使い捨て画面で VisionKit `DataScannerViewController` を実機動作させ、以下を確認
  - [ ] 対応7シンボロジー（JAN-13/8, UPC-A/E, Code128, Code39, QR）が読み取れるか
  - [ ] 読取速度・精度は実用に足るか（小さいバーコード、印刷のかすれ）
  - [ ] `isSupported == false` の端末向け AVFoundation フォールバックの動作確認
- [ ] スパイク結果を `docs/notes/scanner-spike.md` に記録（採用構成の判断根拠）

**完了条件**: 実機でバーコードを読み取り、値がコンソールに出る。スキャナ構成の判断が下りている。

> スパイクで重大な問題が出た場合（読取精度不足など）はここで設計を見直す。後工程への影響が最も大きい不確実性のため、先頭に置く。

## P1: データモデル + 取込

**目的**: 表データをアプリに取り込めるようにする。シミュレータのみで完結。

作業:
- [x] SwiftData モデル実装（`Project`, `Row`, `RowStatus`）
- [x] `TableParser` 実装（RFC 4180、区切り文字自動判定、UTF-8/Shift_JIS）
- [x] `TableParser` 単体テスト（クォート・改行入りセル、空行、列数不揃い、BOM）
- [x] S2 データ取込画面（ペースト / fileImporter）
- [x] S3 プレビュー & 列マッピング画面（自動推定、新規列追加、バリデーション）
- [x] 取込確定 → `Project` 保存(既存コードがある行は「登録済み」化。`ImportPlanner` として Core に実装)

検証: 取込フローの E2E は `BarcodeAssignUITests`(ペースト取込 + CSV ファイル取込)で自動化済み。

**完了条件**: スプレッドシートからコピーした表と CSV ファイルの両方を取り込み、列マッピングして保存できる。パーサのテストが全て通る。

## P2: レコード一覧 + ホーム

**目的**: 取り込んだデータの閲覧・管理と、再開の入口を作る。

作業:
- [ ] S4 レコード一覧（状態アイコン、フィルタ、検索、行スワイプ操作）
- [ ] S1 ホーム（プロジェクト一覧、進捗表示、削除・名前変更、空状態）
- [ ] 画面遷移の結線(S1 → S2 → S3 → S4、S1 → S4)
- [ ] 1,000行規模のダミーデータでスクロール性能確認

**完了条件**: 取込 → 一覧確認 → アプリ再起動 → ホームから同じデータを開き直せる（再開要件の土台）。

## P3: スキャン本実装

**目的**: アプリの中核である連続スキャンフローを完成させる。実機中心の開発。

作業:
- [ ] `BarcodeScannerService` プロトコル + VisionKit 実装 + AVFoundation フォールバック（P0 スパイクのコードを本実装化）
- [ ] S5 スキャン画面 UI（カメラプレビュー、商品情報カード、進捗、操作ボタン）
- [ ] 読取成功フロー: 保存 → 音 → 振動 → 次の未登録行へ自動移動
- [ ] 同一コードのクールダウン（連続誤登録防止）
- [ ] 重複チェック + 警告ダイアログ（登録済み行の情報表示、このまま登録/キャンセル）
- [ ] スキップ / 前へ / 一覧へ / 手動入力
- [ ] 登録済み行の再スキャン時の上書き確認
- [ ] 全行完了画面
- [ ] カメラ権限拒否時の誘導表示
- [ ] `currentPosition` の逐次保存（途中再開）

**完了条件**: 実機で「表示 → スキャン → 自動保存 → 次へ」を 50 件連続で快適に実行できる。途中でアプリを終了しても続きから再開できる。重複警告が機能する。

## リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| VisionKit の読取精度・対応端末の制約 | 中核機能が成立しない | P0 で最初にスパイク検証。AVFoundation フォールバックを用意 |
| CSV の方言（文字コード・クォート） | 取込失敗 | パーサを UI 非依存にして単体テストを厚くする（P1） |
| 大量行でのパフォーマンス | 一覧・保存が重い | P2 で 1,000 行、P5 で 5,000 行の負荷確認 |
| 連続スキャンの誤登録（同一コード連続検出） | データ破損・信頼低下 | クールダウン実装 + P3 完了条件で 50 件連続テスト |

## スコープ外（将来拡張 — PRD 参照）

Google Sheets API / Excel / Shopify / Amazon / WooCommerce / Bluetooth リーダー / OCR / NFC / iCloud 同期。
`BarcodeScannerService` プロトコルと `TableParser` / `Exporter` の分離により、これらは既存画面を変えずに追加できる構成とする。
